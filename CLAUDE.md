# CLAUDE.md — Руководство по проекту «Волна» (Volna)

Добро пожаловать в проект **«Волна»**! Это ультралегкий, нативный десктопный клиент Яндекс Музыки для Linux, написанный на **Rust** с использованием **GTK4 / Libadwaita** и **GStreamer**.

Главная цель проекта — заменить прожорливый официальный Electron-клиент (800+ МБ RAM) на отзывчивое, эстетичное приложение с потреблением до 40 МБ RAM без потери функционала.

---

## 🚀 Быстрый старт и команды

Всегда используй флаг PATH для доступа к тулчейну Rust:
```bash
# 1. Проверка синтаксиса и типов
PATH=$HOME/.cargo/bin:$PATH cargo check

# 2. Запуск тестов (все тесты изолированы и проходят за доли секунды)
PATH=$HOME/.cargo/bin:$PATH cargo test

# 3. Сборка оптимизированного релизного бинарника
PATH=$HOME/.cargo/bin:$PATH cargo build --release

# 4. Запуск приложения
./target/release/volna
```

## ⚠️ Важные соглашения и архитектурные правила (НЕ ЛОМАТЬ!)

### 1. Экран Караоке (`src/ui/window.rs`, `src/ui/style.css`):
- **Нулевой reflow шапки (`GtkOverlay`):** Шапка `k_header` (название трека и артист в левом верхнем углу + круглый стеклянный крестик `✕` в правом верхнем углу) вынесена в отдельный верхний оверлейный слой с `Align::Start`. Она **абсолютно неподвижна** и не двигается ни при каких обстоятельствах.
- **Отсчет 3... 2... 1...:**
  - Реализован крупной парящей неоновой цифрой 82px (`.karaoke-countdown-digit`) в верхней трети экрана (`margin_top: 90px`).
  - **Запускается ИСКЛЮЧИТЕЛЬНО в начале трека** перед первой строкой вокала (`Some(0)`). Никаких отсчетов в середине песни во время пауз!
  - Пока идет отсчет — текст скрыт (`opacity: 0.0`). В момент старта вокала цифра исчезает, текст плавно проявляется (`opacity: 1.0`).
- **Позиционирование текста:** активная строка синхронизированного текста всегда по центру окна: у `lyrics_container` поля сверху и снизу равны полвысоты окна (`apply_lyrics_margins`, класс `synced`). Текст лежит в `gtk::Fixed` и двигается трансформацией (`set_child_transform`), а не прокруткой: `ScrolledWindow` сдвигает только на целые пиксели, и медленная прокрутка шла рывками. Движение — критически задемпфированная «пружина» с шагом не длиннее 1/120 с. Предел сдвига считается по высоте самого текста (размер `Fixed` зависит от сдвига). Без активной строки текст стоит в начале. У обычного текста поля небольшие, он листается прокруткой.
- **Строки:** все строки свёрстаны одним размером, активная только масштабируется (`transform: scale`) — смена `font-size` пересчитывала раскладку всего текста каждый кадр и роняла кадры. Клик по строке перематывает трек к её началу (`AudioBackend::seek_ms`).
- **Смена трека:** пока новый поток не начал играть (позиция > 1,5 с — ещё старая), подсветка ждёт (`awaiting_start`).
- **Открытие/закрытие:** одна анимация прозрачности на всех (`set_karaoke`), элементы экрана Волны гаснут, фон остаётся. Поверх Поиска и Медиатеки подложка плотная (класс `solid`).
- **Чистая типографика текста:** Вокруг активной строки караоке **НЕТ никаких рамок, прямоугольников или полукруглых фонов**. Только чистый крупный белый текст 28px bold с мягким неоновым свечением.
- **Иконка караоке:** Используется фирменная векторная иконка `data/icons/lyrics-symbolic.svg` (стилизованная буква «Т» со строчками текста).

### 2. Бесконечный поток «Волны» (`src/player/manager.rs`):
- Плеер не должен останавливаться после окончания трека: срабатывает сигнал GStreamer `connect_end_of_stream`, вызывается `track_finished`, переключается следующий трек, а если в очереди остается < 2 треков — ротор автоматически догружает новую пачку.

### 2.1. Воспроизведение и повтор (`src/player/manager.rs`):
- **Гонка быстрых кликов:** каждый запрос воспроизведения увеличивает счётчик `generation`; асинхронная задача перед показом обложки, текста и `play_url` сверяется с ним и молча выходит, если устарела. Новые задачи, меняющие трек, обязаны делать то же.
- **Повтор:** `RepeatMode` {Off, One, All}. Для станций Ротора (`state.wave`) режима «вся очередь» нет. В обычной очереди без повтора воспроизведение останавливается на последнем треке, в Волне идёт бесконечно.
- **Дубли в Волне:** один трек бывает в нескольких альбомах под разными id, поэтому очередь фильтруется по названию и исполнителям (`dedup_tracks`, `track_key`), а не только по id.
- **Значок E:** треки с `contentWarning: explicit` помечаются плашкой «E» в `track_row` (`Track::is_explicit`).
- **Плашка типа Волны** сверху на экране волны: фильтр рисует сам интерфейс, «по артисту/по треку» приходит событием `WaveContext`; у простой Волны плашки нет.
- **Качество:** Яндекс через `download-info` отдаёт сторонним клиентам только MP3 (на 2026-10-15 — 192 кбит/с); lossless недоступен. Плашка в плеере показывает реальный формат (`StreamQuality`). FLAC-метод приложения Яндекса не используем (см. правовую заметку в README).

### 2.2. Справка об исполнителях и альбомах:
- Порядок источников: Википедия → Last.fm → Genius (для альбомов Википедия → Last.fm). Страница принимается только при точном совпадении названия и подходящем описании: лучше ничего не показать, чем чужое.
- Ключи Last.fm и Genius хранятся в `config.json` (поля в окне настроек). Без ключей источник пропускается.
- Английский текст (`translate::is_english`) получает кнопку «Перевести на русский» (MyMemory, лимит в день). Тексты Википедии и Last.fm — CC BY-SA, под карточкой всегда подпись источника со ссылкой.
- Тесты, ходящие в сеть, помечены `#[ignore]`: `cargo test wiki -- --ignored --nocapture`.

### 3. База текстов (Яндекс + LRCLIB):
- Приоритет у текста с таймингами: кэш → Яндекс `/supplement` → LRCLIB `/api/get` → LRCLIB `/api/search` (название и исполнитель в любом порядке, длительность ±3 с) → обычный текст.
- Синхронизированный текст годится только от 4 строк (`usable_synced`): в базах бывают огрызки из одной строки. Огрызок Яндекса показывается как обычный текст без таймкодов.
- Если LRCLIB не отвечает, дальше к нему не ходим, чтобы не съесть таймаут 12 с и не потерять текст Яндекса.
- Пословных таймингов нет ни у Яндекса, ни (почти) в LRCLIB; приблизительную подсветку по буквам пробовали и отказались.

### 3.1. Фон Волны:
- Рисует видеокарта (`wave_gl.rs`), процессор каждый кадр только двигает время/бас/цвета и вызывает `queue_render`. Если OpenGL не поднялся (нет EGL, нет GLSL 3.30/ES 3.0), показывается статичный градиент темы (`ambient-backdrop`, `on_fail` в `wave_gl::attach`); `VOLNA_NO_GL=1` имитирует этот случай.
- Бас — `spectrum` в `audio.rs`, полосы 40–150 Гц, со сдвигом под звучащий фрагмент.
- Цвет: сначала `derivedColors` Яндекса, после загрузки обложки — её самый насыщенный тон (`palette_from_pixels`); бесцветная обложка цвет не меняет.

### 3.2. Клипы на фоне (`wave_clip.rs`, `wave_gl.rs`):
- Настройка `clips` в `config.json` (по умолчанию выключена). Ссылка на превью берётся из `/tracks/{id}/supplement` (`clips[0].previewUrl`, только https и хост `*.yandex.net`), файл кэшируется в `~/.cache/volna/clips/` (лимит 30 МБ на файл), очищается кнопкой «Очистить память».
- Декодирование: GStreamer (`filesrc ! decodebin ! … ! appsink`, RGBA, ширина 640) в потоке декодера; кадр кладётся в `ClipShared`, `wave_gl` загружает его текстурой и смешивает в шейдере (cover, прозрачность 0.30, плавное проявление). Петля — перемотка на EOS. Звук клипа не воспроизводится.
- Приходит событием `ClipUpdated(Option<path>)`, `TrackStarted` сбрасывает клип. Проверка без аккаунта: `VOLNA_DEMO_CLIP=путь.mp4`.
